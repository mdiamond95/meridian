## 1. Release 1.0.2 (branch `pack-immutability`)

Decisions are under **2026-10-05 — Release 1.0.2** in `docs/decisions.md`.

### Before building
Two items rested on fields that are not as the brief described, and Mark chose:
- `meta.id` is a slug for presets, not a content hash, so the test computes a canonical-JSON hash
  itself.
- There is no `meta.schemaVersion`, so the consumer rule checks the top-level `version === 1`.

### Built, by brief item
1. **Published packs are immutable.**
   - `npm run packs:check -w app` compares every file under `packs/` with the previous release tag,
     as canonical JSON, and fails on a pack changed or deleted. `index.json` is exempt. It runs in the
     CI app job, which now fetches full history.
   - Checked by hand against `v1.0.1`: clean passes (5 packs); one pack edited and another deleted
     fail with both named and exit 1; a pack reformatted with indentation passes. Against `v1.0.0`:
     4 packs, unchanged.
   - `npm run presets` writes a changed pack to `<slug>.<meshVersion>.<n>.json` and moves
     `index.json`; it never overwrites. Run on this branch, it wrote nothing.
   - Unit tests for names, the choice of file and the violations: `app/src/import/packFiles.test.ts`.
2. **docs/interop.md.**
   - A "Consumer rules" section: pin a release tag; read regions (polygons, stats, scores), not cells;
     ignore unknown fields; check `format` and `version === 1` and refuse otherwise.
   - Every example URL pinned to `v1.0.1`; the `main` row removed from "Where packs live".
   - Versioning rule 7, published packs are immutable, and the numbered file names.
   - The Leaflet snippet checks format and version, still twenty lines. The House of Cards fetch is
     run as written by the test.
   - New tests: every `BASE` is a `vX.Y.Z` tag with the files it fetches (fails when one is set back
     to `main`, checked); `getScores` refuses version 2; the smoke spec checks the snippet's pin.
